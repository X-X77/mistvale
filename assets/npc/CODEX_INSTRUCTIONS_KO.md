# Codex 작업 지시문 — 미스트베일 NPC 2명 실배치

기존 미스트베일 사이트를 보존하면서 동봉된 MISTVALE_NPC_Starter 폴더를 프로젝트의 assets/npc/ 아래에 병합하세요. 기존 오프닝(X_XPLAY → 타이틀 → 로딩 → 현실)은 수정하지 마세요.

## 데이터/경로
- assets/npc/characters.json을 읽고 npc.rowen, npc.edelin 정보를 사용하세요.
- asset path들은 assets/npc/을 기준으로 한 상대 경로입니다. 경로를 정확히 조합하세요.
- 캐릭터 파일명은 rowen, edelin. 화면 이름은 로웬, 에델린.
- 기존 장소 지도/상세 화면의 데이터 구조가 있다면 그 구조에 연결하세요. 새로 중복 NPC 관리 시스템을 만들지 마세요.
- 로웬은 클로버 잡화점(09:00–18:00), 에델린은 작은 도서관 사서. 도서관의 영업시간은 정해지지 않았으므로 임의로 만들지 마세요.
- 작은 도서관이 지도에 없다면 맵 데이터에 추가하되 기존 장소와 배치를 훼손하지 마세요.

## 화면/동작
- 시설 클릭 → 실내 배경 표시 → 해당 NPC의 작은 전신 도트(A)를 별도 레이어에 배치.
- 작은 도트 PNG는 투명 128×128이며, image-rendering: pixelated; object-fit: contain; 로 원본 비율 유지.
- A 이미지는 idle 정지 상태를 기본으로 하고, 파일이 있는 경우에만 클릭 시 다른 포즈로 바꿀 수 있습니다. 로웬은 idle만 제공되므로 work/greet를 참조하지 마세요. 에델린은 read/work/greet가 제공됩니다. 포즈 이미지를 빠르게 왕복시키면 동작이 끊겨 보이므로 빠른 프레임 애니메이션으로 쓰지 마세요.
- NPC 클릭 시 이름+대사+큰 초상(B) 나타내기, 다음 대사/닫기/되돌아가기 정상 작동.
- B는 portrait.default를 우선 사용하되, 나중에 originalPortrait 경로로 교체 가능한 설정 한 곳으로 분리하세요. A는 B 변경으로 영향받지 않아야 합니다.
- 대사는 characters.json의 lines를 참고하고 기존 캐릭터 말투를 보존하세요. {{user}}를 실제 이용자 이름으로 치환할 수 없다면 그대로 인물 이름처럼 출력하지 말고 중립적인 호칭으로 처리하세요.
- 에셋이 없을 때 페이지 전체가 깨지지 않도록 이미지 로드 실패 fallback 처리.

## 중요: 소스 퀄리티 제한
- 기존 이미지는 여러 포즈를 합성한 콘셉트 시트에서 추출한 시험용 PNG입니다. A 포즈에 가장자리 마스킹 잔여물이나 프레임 간 비율 차이가 있을 수 있으므로 우선 실제 사이트에서 크기/정렬을 검증해 주세요.
- 실제 walk cycle, 고품질 작업 애니메이션이라고 주장하지 마세요. 먼저 정지 NPC, 클릭 효과, 대화 전환을 안정적으로 완성하세요.

## 검증
- 두 캐릭터가 올바른 장소에서 보이는지, PNG 투명이 적용됐는지, 모바일에서 잘리지 않는지 확인.
- 대사/초상 교체/닫기/시설 이동이 정상인지 확인.
- 기존 오프닝, 갤러리, 기타 장소 기능이 유지되는지 확인.
- 기존 GitHub Pages의 배포 충돌 경험이 있으므로 코드 커밋 성공과 실제 배포 성공을 엄격하게 구분. Actions 성공 여부 및 실제 사이트를 확인한 후 보고.
- 배포 설정 변경, 기존 파일 삭제, 원본 에셋 교체는 반드시 필요한 경우에만 하세요.

주의: 로웬 work/greet는 이미지 분리 오류로 최종 패키지에서 제외되어 있습니다. 없는 파일을 요청하지 마세요.
